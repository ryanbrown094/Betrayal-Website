# The Betrayal

A hosted party game for 8–24 players, in two ways to play. Classic: the TV (a laptop cast to it) runs the show and the
Keeper's phone runs the game. Modern: everyone plays on their own phone and the server runs the game.
Sold as a booking: a one-party booking code (£10) opens one Table for 48 hours; a Regular's code (£20 a month) opens a
new Table whenever they like, one at a time. Many parties play at once, each at its own Table.

- Home page: `https://thebetrayal.co.uk/`: book a Table, open one with a booking code, join one
- A Classic Table: `https://thebetrayal.co.uk/t/ROOMCD` (TV) and `…/t/ROOMCD#keeper` (Keeper phone)
- A Modern Table: phones join at `/join` or `/m/ROOMCD`; `/t/ROOMCD` is its TV
- Staging: `https://staging.thebetrayal.co.uk/`

Read `HANDOVER.md` before changing anything.

## Layout

```
src/            the game pages, split by job: build.sh concatenates them (no framework, no bundler)
  content.js    mission definitions and content banks (append-only)
  scripts.js    every host line and the night / ceremony scripts
  core.js       store and sync, rooms, the game plan (RULES0, planMissions, autoPrize, autoMode), every rule
  audio.js      synthesised sound and the adaptive score
  art.js        every drawing (inline SVG), including the crest (ART.crest)
  tv.js         the TV renderer
  host.js       the Keeper's phone: the game-plan setup, then every phase
  diag.js       the trail of taps and errors, "Report a problem", the admin replay
  boot.js       startup, build auto-reload, wake lock
  modern-ui.js  Modern's page: every phone, the director and the optional TV
  qr.js         the join QR code
  style.css, modern.css, fonts.css
site/index.html the home page (sell, redeem a booking code, join a Table, claim after checkout)
site/pages/     the other pages (buy, rules, tour, legal, contact, admin), wrapped in site/page.html by build.sh
worker/         Cloudflare Worker: src/index.js (router, GameState room object, Registry booking-code object), src/codes.js,
                src/rules.js (save rules), src/public-view.js (what the TV may see), src/modern.js (Modern's rules engine),
                src/content.gen.js (generated by build.sh). Config: wrangler.toml / wrangler.staging.toml at the repo root
media/          brand: logos, screenshots (qa/media.py), social, palette, copy, guidelines
tools/          brand/ (logos, guidelines, creatives, seal), marketing-pack.py, passes.sh (admin), stripe-setup.sh
qa/             test harnesses (see HANDOVER §8)
```

## Build, test, run locally

```sh
./build.sh                                   # → index.html (standalone game), worker/public/{play.html,modern.html,index.html,media/,build.txt}
python3 qa/smoke166.py                       # rules checks (own server): about 3 min
python3 qa/plan.py                           # the game plan: every setup choice honoured: about 1 min
node qa/claim.mjs                            # Stripe claim path, stubbed
node qa/server.mjs 8714 & python3 qa/e2e.py  # sync, PIN, redaction, whole-game flow (single default room)

# the real Worker, rooms and booking codes included:
npm i && npx wrangler dev --port 8790 --var ADMIN_TOKEN:dev --var SITE_PASSWORD: --var BUILD:$(cat worker/public/build.txt)
ADMIN_TOKEN=dev python3 qa/e2e.py http://127.0.0.1:8790/     # booking codes, rooms, isolation and the game
BASE=http://127.0.0.1:8790 ADMIN_TOKEN=dev tools/passes.sh mint 3 "testing"
```

## Deploy

```sh
CLOUDFLARE_API_TOKEN=… ./deploy.sh staging
ADMIN_TOKEN=… python3 qa/e2e.py https://staging.thebetrayal.co.uk/
CLOUDFLARE_API_TOKEN=… ./deploy.sh production
```

Deploys don't wipe games. Once, per environment: `npx wrangler secret put ADMIN_TOKEN -c wrangler.toml`
(and `STRIPE_SECRET_KEY` when payments are live).

## Selling booking codes

- **By hand:** `/admin` (Booking codes), or `tools/passes.sh mint 10 "launch friends"`, which prints codes (`OATH-XXXX-XXXX`). Send one per party.
- **Stripe Checkout** (the `/buy` page): once per environment, run
  `STRIPE_SECRET_KEY=sk_… tools/stripe-setup.sh https://<domain> <price-in-pence>`. It creates the product, the price
  and the webhook endpoint. Put the printed `price_…` in `STRIPE_PRICE_ID` in that environment's wrangler `.toml`
  (the Regular's monthly price goes in `STRIPE_SUB_PRICE_ID`), then `npx wrangler secret put STRIPE_SECRET_KEY` and
  `… STRIPE_WEBHOOK_SECRET` (the printed `whsec_…`). Show the price in `SHOP` (`site/index.html`) and on
  `site/pages/buy.html`. Test keys on staging, live keys on production.
  The buyer ticks the two consent boxes, pays on Stripe, and comes back to the home page with their booking code on
  screen. See HANDOVER §6.2.
- `tools/passes.sh list` shows every code, whether it was redeemed, its room and when it runs out; `revoke` cancels one.

## The domain, GitHub and the password gate

- **Domain:** `thebetrayal.co.uk` (and `www.`) is the production Worker's custom domain in `wrangler.toml`; staging is `staging.thebetrayal.co.uk`. `cloakandcandle.co.uk` is attached too and redirects every page to `thebetrayal.co.uk` (`OLD_HOSTS`); the API answers on it. Cloudflare creates the DNS records on the first deploy.
- **The repos:** this one is [ryanbrown094/Betrayal-Website](https://github.com/ryanbrown094/Betrayal-Website) (renamed from `ryanbrown094/Claude`; GitHub redirects the old name), and the iPhone app is [ryanbrown094/Betrayal-App](https://github.com/ryanbrown094/Betrayal-App).
- **GitHub → Cloudflare:** with the repo connected to the Worker (Workers & Pages → the Worker → Settings → Build), every push to `main` runs `npx wrangler deploy` at the repo root. The built pages in `worker/public` are committed, so **run `./build.sh` before you commit**: Cloudflare does not run it. The Worker's name in Cloudflare must match `name` in `wrangler.toml` (`cloak-and-candle`, the name its Durable Objects are bound to).
- **Password gate (pre-launch):** `SITE_PASSWORD` in an environment's [vars] (staging and previews set it) locks every page, asset and API call behind a password page (a 30-day cookie once it's entered). `/api/admin/*` skips it (it has its own token). Delete the line and deploy to open the site. The password is visible to anyone who can read the repo: keep the repo private.
